Acuarius · API v1

Conecta tu sistema al CRM

La API de Acuarius deja que un sistema externo —el agente de IA de tu empresa, tu app, tu ERP— gestione el CRM como una persona del equipo: leer prospectos, moverlos de etapa, cerrarlos, asignarlos, dejar notas y agendar tareas y citas. Y con los webhooks, Acuarius le avisa a tu sistema cuando pasa algo.

Empezar

1. En Acuarius, entra a Configuración → API y agentes y crea una llave. Ponle el nombre que quieres ver firmado en el historial («Agente de seguimiento») y marca solo los permisos que necesita. La llave se muestra una sola vez.

2. Envíala en cada llamada, en la cabecera Authorization:

curl https://app.acuarius.app/api/v1/leads?estado=abiertos \
  -H 'Authorization: Bearer acu_live_…'

La dirección base es https://app.acuarius.app/api/v1. Todo va y viene en JSON. Las fechas con hora van en ISO 8601 con zona horaria (2026-10-09T15:00:00-05:00); sin zona se rechazan, porque «las 3» en Bogotá y en Madrid son horas distintas.

La llave da acceso a tu cuenta: úsala solo desde un servidor, nunca en una página web ni en una app que se instale en el teléfono. Por eso la API no responde a llamadas desde un navegador. Si una llave se filtra, revócala en Configuración: deja de funcionar en ese mismo momento.

Las reglas

Las mismas que una persona. La API no tiene atajos: mover a Ganado pide motivo y sella la fecha de cierre; cerrar anula las tareas pendientes; cada cambio dispara las automatizaciones de la cuenta y, al ganar, la venta se reporta a las plataformas de pauta conectadas. Una etapa que pide agendar una cita no se puede alcanzar sin la cita.

Todo queda firmado. Cada cambio aparece en el historial del prospecto con el nombre de la llave, igual que si lo hubiera hecho alguien del equipo.

Nunca borra. No existe ninguna ruta para borrar prospectos, tareas ni notas.

No toca Marketing. La API no envía campañas ni mensajes, y no crea ni cambia automatizaciones, páginas de aterrizaje, formularios, plantillas ni listas. Eso lo maneja tu equipo desde Acuarius. Si mover un prospecto de etapa cumple la condición de una automatización que tu equipo creó, esa automatización corre igual que si lo hubiera movido una persona.

Seguridad de las llaves. Para crear una llave o un webhook hay que tener activa la verificación en dos pasos. Al dueño de la cuenta le llega un correo cada vez que alguien crea o revoca una llave, o añade, cambia o elimina un webhook. Si quien creó una llave o un webhook era un administrador del equipo y deja de serlo (lo sacan o le cambian el perfil), su llave se revoca y su webhook se desactiva solos.

Tu responsabilidad. Lo que haga un sistema con tu llave se considera hecho por tu cuenta, y al conectarlo decides enviarle datos de tus contactos. Lo explican la sección 11 de los Términos y la Política de Tratamiento de Datos.

Plan. La API está en los planes Pro y Agency (y durante la prueba de 14 días). Si la cuenta pasa a gratis, sus llaves dejan de funcionar.

Límites

Cada llave tiene 120 llamadas por minuto, de las cuales como mucho 30 pueden ser cambios (POST o PATCH), y 20.000 llamadas por día (el día se reinicia a medianoche UTC). Además, entre todas las llaves de una cuenta caben 300 llamadas por minuto. Cada respuesta trae cuánto llevas: X-Uso-Minuto, X-Limite-Minuto, X-Uso-Dia y X-Limite-Dia; GET / muestra todos los límites. Al pasarte recibes 429 con Retry-After en segundos. Las listas devuelven como mucho 100 elementos por página. Si tu caso necesita más, escríbenos.

Reintentos seguros

Si se corta la red justo después de pedir algo, no sabes si se hizo. Envía en los POST y PATCH una cabecera Idempotency-Key con un identificador tuyo (hasta 100 caracteres): si repites la llamada con la misma clave en las 24 horas siguientes, recibes la primera respuesta con la cabecera Idempotent-Replayed: true y no se crea nada dos veces.

Mover de etapa y cerrar

POST/leads/{id}/etapaleads:etapa

etapa acepta la clave (calificado) o el nombre que ve el equipo («Visita al concesionario»). Si no existe en el proceso del prospecto, la respuesta trae la lista de las que sí.

// Mover
{ "etapa": "calificado" }

// Cerrar como ganado: el motivo es obligatorio y tiene que ser uno de /motivos-cierre
{ "etapa": "ganado", "motivo": "Compró el vehículo",
  "valor": 95000000, "moneda": "COP", "fecha_cierre": "2026-10-08",
  "nota": "Firmó en el concesionario de la 80" }

// Etapa que pide cita (pide_cita: true en /procesos)
{ "etapa": "Visita al concesionario",
  "cita": { "inicio": "2026-10-10T10:00:00-05:00", "titulo": "Test drive",
            "invitar_lead": true } }

// Pasar a otro proceso (y opcionalmente a una etapa de ese proceso)
{ "proceso": "id-del-proceso", "etapa": "nuevo" }

Al cerrar se sella la fecha de cierre (el día de fecha_cierre, o ahora) y se anulan las tareas pendientes del prospecto. Ganar sin valor se permite, pero la respuesta lo advierte en avisos: la venta llegaría sin importe a la pauta y a los reportes. Volver a abrir un prospecto cerrado limpia su fecha de cierre. Si la cuenta tiene Google Calendar conectado, la cita se crea también allí, y con invitar_lead al prospecto le llega la invitación.

Responde con un 2xx en menos de 8 segundos. Cualquier otra cosa (incluida una redirección) cuenta como fallo y se reintenta a los 1, 5 y 15 minutos y a las 1, 4 y 12 horas. Un webhook con 200 fallos seguidos y ningún aviso entregado en tres días se desactiva solo, y Configuración dice por qué.

Comprobar la firma

La firma es un HMAC-SHA256, con tu secreto, de t + . + el cuerpo tal como llegó. Rechaza los avisos con t de hace más de 5 minutos.

import crypto from 'node:crypto';

function avisoValido(cuerpoCrudo, cabeceraFirma, secreto) {
  const { t, v1 } = Object.fromEntries(cabeceraFirma.split(',').map(p => p.split('=')));
  if (Math.abs(Date.now() / 1000 - Number(t)) > 300) return false;
  const esperada = crypto.createHmac('sha256', secreto).update(t + '.' + cuerpoCrudo).digest('hex');
  return crypto.timingSafeEqual(Buffer.from(esperada), Buffer.from(v1));
}

Para agentes de IA

La API está pensada para que la use un agente con herramientas (por ejemplo, uno hecho con Claude). Algunas recomendaciones:

Una herramienta por ruta. Dale al agente buscar_prospectos (GET /leads), ver_prospecto (GET /leads/{id}), mover_etapa, crear_tarea, dejar_nota… y que consulte /procesos y /motivos-cierre al empezar, en vez de adivinar etapas o motivos.

Deja que los errores le enseñen. Los mensajes están escritos para que un modelo los entienda y corrija solo: una etapa inexistente devuelve las válidas; un cierre sin motivo, los motivos de la cuenta.

Usa Idempotency-Key en todo lo que escriba: un agente reintenta más que una persona.

Una llave por agente, con su nombre: así el historial dice cuál de tus agentes hizo cada cosa, y puedes apagar uno sin tocar a los demás.

Servidor MCP

Si tu agente habla MCP (Model Context Protocol), no tienes que programar las herramientas: conéctalo a https://app.acuarius.app/api/mcp con la misma llave y verá solo las herramientas del CRM que esa llave permite, con su explicación (buscar_prospectos, ver_prospecto, mover_etapa, crear_tarea, dejar_nota…). Pasan por las mismas reglas, permisos, límites y firma que la API, porque por dentro son la API.

Con la API de Claude (conector MCP):

curl https://api.anthropic.com/v1/messages \
  -H 'x-api-key: TU_CLAVE_DE_ANTHROPIC' -H 'anthropic-version: 2023-06-01' \
  -H 'anthropic-beta: mcp-client-2025-11-20' -H 'content-type: application/json' \
  -d '{
    "model": "claude-opus-5-5", "max_tokens": 16000,
    "mcp_servers": [{ "type": "url", "name": "acuarius",
                      "url": "https://app.acuarius.app/api/mcp",
                      "authorization_token": "acu_live_…" }],
    "tools": [{ "type": "mcp_toolset", "mcp_server_name": "acuarius" }],
    "messages": [{ "role": "user",
      "content": "¿Qué prospectos abiertos llevan 5 días sin movimiento?" }]
  }'

Con Claude Code:

claude mcp add --transport http acuarius https://app.acuarius.app/api/mcp \
  --header "Authorization: Bearer acu_live_…"

Transporte «Streamable HTTP» sin sesión (cada mensaje por POST, respuesta en JSON). Cada petición al servidor MCP comprueba la llave y luego ejecuta la herramienta, así que cuenta dos llamadas en tu límite por minuto. Por ahora se entra solo con la llave: conectar Acuarius desde la aplicación de un asistente sin copiar llaves (con inicio de sesión) llegará más adelante.
